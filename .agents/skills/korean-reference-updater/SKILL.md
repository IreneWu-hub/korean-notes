# 韓語文法與單字庫更新統整 Skill (Korean Reference Updater)

本 Skill 專門用於將累積數堂的韓語上課筆記（`static/lessons/lesson-*.html`），**系統化抽取文法、助詞、數詞量詞與情境單字**，擴充至 `docs/reference/` 專題資料庫中，並**同步記錄目前統整至第幾課**。

---

## 🎯 觸發時機 (Trigger Conditions)

當用戶提出以下需求時觸發：
1. 「幫我檢視文法與單字庫需要補哪些內容」
2. 「把最近幾堂課的重點/文法/單字統整進資料庫」
3. 「更新文法與單字庫並推進進度至 Lesson N」
4. 「查看目前文法單字庫統整到第幾課」

## 🛠️ 標準執行作業流程 (Workflow)

```mermaid
flowchart TD
    A["1. 讀取當前進度與掃描課堂<br/>(檢查 GEMINI.md 與 index.mdx)"] --> B["2. 盤點待統整課堂<br/>(分析 static/lessons/ 內容)"]
    B --> C["3. 抽取重點並歸類四大主題<br/>(動詞時態 / 助詞 / 數詞 / 單字)"]
    C --> D["4. 編輯與擴充 docs/reference/ 檔案<br/>(善用發音組件與表格)"]
    D --> E["5. 推進進度看板<br/>(更新 index.mdx 與 GEMINI.md)"]
    E --> F["6. 構建驗證<br/>(執行 npm run build 確保零錯誤)"]
```

### 步驟 1：檢視目前統整進度 (Inspect Status)
1. 讀取 `GEMINI.md` 或 `docs/reference/index.mdx` 中的看板記錄，找出**「已統整收錄課堂」**（例如：`Lesson 01 ~ Lesson 11`）。
2. 列出 `static/lessons/` 下的所有 `lesson-*.html`，比對出**待更新課堂清單**（例如：目前已開課到 `lesson-014.html`，則待補範圍為 `Lesson 12 ~ Lesson 14`）。

### 步驟 2：課堂精華深度抽取與篩選 (Content Extraction & Filtering)

> [!IMPORTANT]
> **🔍 收錄篩選原則：精選重於全收，以 TOPIK 範圍為優先參考**
> 部分課堂可能偏向特定旅遊情境或文化知識補充，**不需要將課堂出現的所有字詞與內容全部加入統整**。抽取時請務必評估「重要性」與「常見度」，並以 **TOPIK 檢定範圍（特別是 TOPIK I 1~2 級及 TOPIK II 基礎常用範圍）** 作為主要參考基準：
> - ✅ **優先收錄**：TOPIK 高頻核心文法與助詞、常用基礎動詞／形容詞、實用生活與旅遊通用高頻詞彙（如交通、時間方位、基礎點餐／購物／問路動作、常見狀態）。
> - ⏭️ **可略過不收錄**：偏知識性或文化科普的專有名詞、僅在單一冷門旅遊場景出現的詞彙、過於瑣碎的特定品項名稱（如小眾菜單、特定景點名）、以及低復現率的純補充外來語。這些內容保留在原本的 `lesson-*.html` 筆記中複習即可，不必塞入速查庫。

仔細閱讀待補課堂的 HTML 內容，依下列四大面向**過濾並提取高價值重點**：
1. **動詞/形容詞文法**：
   - 是否出現具備通用構句價值的核心時態、假設句、願望或義務/請求語法（TOPIK 常見考點優先）？
   - 是否出現特殊不規則動詞/形容詞（如 `ㄷ`、`ㅅ`、`ㅎ`、`ㅡ`、`르` 音變）？
   - 是否有語氣辨析（如過去式感想、去回層次）？
2. **助詞與句型結構**：
   - 是否有高頻新格助詞、副詞格助詞、連接詞或語氣反問？
   - 空間或時間搭配公式。
3. **數詞、量詞與代名詞**：
   - 是否涉及固有詞、漢字詞、常用單位量詞或修飾形態變化？
4. **實用高頻情境單字**：
   - 篩選出符合 TOPIK 基礎核心或日常生活高復現率的詞彙（如機場、飯店、醫院、餐館、超商等通用核心字）；冷門或知識性補充字詞請果斷略過。

### 步驟 3：分流更新至 docs/reference/ 各檔案
- **更新 `conjugation.mdx`**：
  - 說明文法規則、接續公式（無收音/有收音）、實用例句與 **TOPIK 高頻考點／規則例外對比**（如 `ㄷ`/`ㅂ` 規則與不規則對照）。
  - 使用 `<KoreanWord />` 與 `<KoreanAudio />` 標註發音。
- **更新 `particles.mdx`**：
  - 清楚說明助詞功能、接續規則、**TOPIK 易錯辨析**（如必搭否定、地點 vs 時間助詞限制）。
  - 附帶多組雙語實用對話或例句。
- **更新 `numbers.mdx`**（若有數詞相關新主題）：
  - 補充數詞或計量單位，維持 `<NumberTransformGrid />` 或對照表，並標註**固有詞 vs 漢字詞搭配陷阱**。
- **更新 `vocabulary.mdx`**：
  - 僅將**經篩選後的高頻核心單字**依情境歸入現有或新增章節（不追求逐課全收）。
  - **一律使用 `<VocabTable items={[...]} />` 封裝**（切勿改用純 Markdown 表格，才能自動享有發音按鈕、遮韓文／遮中文自測、隨機洗牌與區塊連播），包含 `ko`, `zh`, `ex` 欄位（不需填寫羅馬拼音），核心單字適時搭配簡短觀念例句。

### 步驟 4：推進統整進度記錄（雙重同步）
必須同步更新以下兩處的進度記錄：
1. **`docs/reference/index.mdx`**：
   ```markdown
   :::info[📌 資料庫統整進度追蹤看板 (Status Tracker)]
   * **當前已統整收錄課堂**：**Lesson 01 ~ Lesson {NEW_NUM}** ✅
   * **收錄課程時間跨度**：{START_DATE} ~ {END_DATE}
   * **待補充更新課堂**：暫無（累積數堂課後再進行下一批次統整）
   * **最後更新時間**：{TODAY}
   :::
   ```
2. **`GEMINI.md`**：
   ```markdown
   2. **目前資料庫統整進度**：
      - **已統整收錄課堂**：**Lesson 01 ~ Lesson {NEW_NUM}**
      - **待更新收錄課堂**：**暫無（累積數堂課後再進行下一批次統整）**
   ```

### 步驟 5：構建測試與排版驗證 (Build Verification)
在終端執行構建指令：
```powershell
npm run build
```
- 確認無 broken link（檢查相對路徑是否均為 `./filename.mdx`）。
- 確認無 MDX 表達式解析錯誤（**注意避坑：MDX 內不可直接使用未跳脫的 `{}` 字符**，公式應用引用區塊或代碼區塊呈現）。

## ⚠️ 重要避坑指南 (Pitfalls & Best Practices)

1. **避免在 MDX 中裸寫 `{}`**：
   - MDX 會將 `{}` 視為 JSX expression。若要在文章中展示語法公式，請使用引言區塊：
     `> [物體] + 이/가 + [方位] + 에 있어요`
     而不要在正文中裸寫 KaTeX 的 `$$\text{...}$$`，以免觸發 `acorn` 解析中斷。
2. **單字庫必須能點擊發音**：
   - 所有韓語單字與短句必須帶有真人發音按鈕（使用 `<KoreanAudio text="..." />` 或 `<VocabTable />`）。
3. **保持章節易讀性**：
   - 每個新增章節均需附帶接續規則（無收音 / 有收音 / 特殊音變）與至少 2~3 個生活旅遊高頻實用例句。
4. **寧缺勿濫，拒絕「搬磚式全收」**：
   - `docs/reference/` 的定位是「高頻核心速查庫」，而非課堂筆記的逐字備份。若當堂課偏向旅遊冷門細節或知識性補充，務必以 **TOPIK 範圍與日常復現率**把關，只收錄真正重要、常見的內容。
